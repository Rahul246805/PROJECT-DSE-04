# Mate.ai Production Deployment

Mate.ai deploys as two services:

- `FRONTEND` on Vercel as a Vite React single-page app.
- `BACKEND` on Render as the Express API at `/api/*`.

The production auth path is the built-in local JWT flow, including email/password accounts and guest login. Do not set Clerk or Firebase environment variables unless you intentionally switch auth providers later.

## Render Backend

Create a Render web service from this repository using `render.yaml`, or configure it manually:

- Build command: `npm install --prefix BACKEND`
- Start command: `npm start --prefix BACKEND`
- Health check path: `/health`

Required environment variables:

```text
NODE_ENV=production
MONGO_URI=<MongoDB Atlas connection string>
JWT_SECRET=<long random secret>
GROQ_API_KEY=<Groq API key>
GROQ_MODEL=llama-3.3-70b-versatile
GROQ_MAX_TOKENS=700
FRONTEND_URL=https://<your-vercel-app>.vercel.app
PUBLIC_APP_URL=https://<your-vercel-app>.vercel.app
```

Do not set `SERVE_FRONTEND` on Render for the two-service Vercel + Render deployment. The backend will respond as an API service even if old static files exist in `BACKEND/public`.

The deployed Vercel domains are allowed by default in CORS, but still set `FRONTEND_URL` and `PUBLIC_APP_URL` to the final frontend URL so password-reset links use the correct site.

Optional email/contact variables:

```text
CONTACT_RECEIVER_EMAIL=
MAIL_FROM=
SMTP_HOST=
SMTP_PORT=
SMTP_SECURE=false
SMTP_USER=
SMTP_PASS=
```

## Vercel Frontend

Create a Vercel project from the same repository with root directory `FRONTEND`.

- Framework preset: Vite
- Build command: `npm run build`
- Output directory: `dist`

Required environment variable:

```text
VITE_API_URL=https://<your-render-service>.onrender.com/api
```

Optional display variables:

```text
VITE_LINKEDIN_URL=
VITE_CONTACT_EMAIL=
```

Leave `VITE_CLERK_PUBLISHABLE_KEY` and all `VITE_FIREBASE_*` values unset for local JWT auth.

## GitHub Auto-Deploy

1. Push the deployment-ready branch to GitHub.
2. Connect Render to the repository so commits redeploy the backend.
3. Connect Vercel to the repository with root directory `FRONTEND` so commits redeploy the frontend.
4. After Vercel creates the frontend URL, set that URL in Render as `FRONTEND_URL` and `PUBLIC_APP_URL`.
5. After Render creates the API URL, set `VITE_API_URL` in Vercel to `https://<render-service>.onrender.com/api`.

## Verification

- Render: `GET /health` and `GET /api/health` return a healthy JSON response.
- Vercel: refreshing `/`, `/login`, `/register`, `/forgot-password`, `/reset-password/test`, and `/app` does not produce a 404.
- Auth: register, login, guest login, logout, and protected route redirects work.
- Chat: create chat, send message, edit/regenerate prompt, delete chat, and reload persisted history from MongoDB.
- AI: with a valid `GROQ_API_KEY`, chat replies are generated by Groq and saved in MongoDB.
